## 一、关键技术与问题9 - RAG 检索阈值动态化、回答引用标注信息缺失与同轮对话重复回答问题

【描述系统设计阶段考虑到的可能遇到到的关键技术与问题，包括未知解决方法的问题、未使用过的技术等所有可能影响系统开发的点】

本报告记录了系统在 RAG 检索管道与对话生成环节发现的三个关联问题：①分类器为不同问题类型设计了差异化检索阈值，但该阈值始终未被传入 `VectorService.search()`，系统永远使用配置文件的固定值 `0.65` 进行过滤；②AI 在回答中引用知识库内容时，只输出 `【参考资料1】` 等编号，没有具体说明出处章节，用户和教师无法核对引用来源；③在同一对话框中连续两次提问完全相同的问题，AI 会逐字给出相同回答，而在不同对话框（新会话）中则不会出现此现象。这三个问题分别涉及服务层参数传递断链、Prompt 指令不完整以及消息保存时序引起的上下文污染，需各自独立修复并相互配合。

### 1.1 问题描述

**问题 A：RAG 检索阈值固化，动态分类配置完全失效**

1. `utils/question_classifier.py` 的 `RETRIEVAL_CONFIGS` 已为 6 种问题类型配置了差异化阈值（`error` 类 0.50、`concept` 类 0.60、`general` 类 0.70 等），分类结果以 `threshold` 字段通过 `classification.get('threshold', ...)` 读入 `llm_service.py` 的 `_build_messages()`
2. 然而 `VectorService.search()` 的方法签名为 `search(query, top_k, filter_metadata)`，没有 `threshold` 参数，内部直接硬编码 `threshold = Config.SIMILARITY_THRESHOLD`（值为 `0.65`）
3. 结果：`_build_messages()` 中读取的 `threshold` 局部变量从未传入检索调用，既没有过滤，也没有参与第二层分支判断，分类器的精心设计被彻底架空

**问题 B：AI 引用标注只有编号，缺少章节出处**

1. `_format_knowledge_detailed()` 已将每条资料的 `source`（文件名）、`chapter`（章节）、`section`（小节）格式化后注入 `system` 消息
2. 但高置信度和中置信度的 Prompt 指令仅要求 AI 使用 `【参考资料X】` 格式，未要求同时标注章节名称
3. LLM 严格遵守指令，只输出编号，导致最终回答中出现 `【参考资料1】【参考资料2】` 而无任何来源信息，教师核查和学生溯源均无法进行

**问题 C：同对话框重复提问得到完全相同的回答**

1. 原始 `chat_stream()` 的执行顺序：**先**调用 `ChatService.save_message()` 将当前用户消息写入数据库，**再**调用 `_build_messages()`（内部再次调用 `get_context_for_ai()`）
2. `get_context_for_ai()` 从数据库取出**全部**历史消息（包含刚刚写入的当前消息），而 `_build_messages()` 末尾又显式追加一次 `{"role": "user", "content": user_message}`，导致当前问题在发送给 LLM 的消息列表中出现两次
3. 第二次提同一问题时，context 中包含：上一次的用户问题 + 上一次的完整回答 A1 + 本次问题（重复），加上 `temperature=0.3` 的近确定性输出，以及相同的 RAG 检索结果，LLM 几乎必然逐字重现 A1
4. 新对话框不出现此问题，因为历史里没有 A1 作为锚点，`temperature=0.3` 的随机性勉强足以产生轻微措辞差异

### 1.2 可能的解决方案

**问题 A 修复方案对比：**

| 方案                                                             | 实现路径                                                                  | 一致性                                              | 侵入性               |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------- | -------------------- |
| 给 `search()` 增加 `threshold` 可选参数（已选）                  | 修改方法签名，调用方传参，不传则默认 `Config.SIMILARITY_THRESHOLD`        | 高：调用方完全控制                                  | 低：只加一个可选参数 |
| 在 `_build_messages()` 中调用 `search()` 后再按 `threshold` 过滤 | 不改 `search()`，调用后手动 `[d for d in raw if d['score'] >= threshold]` | 中：`search()` 内部仍用旧阈值取向量，可能浪费结果槽 | 低                   |
| 将 `threshold` 存入 `Config` 并在 `search()` 内读取              | 每次请求更新全局配置                                                      | 低：线程不安全                                      | 高                   |
| 将分类器 `threshold` 作为 `filter_metadata` 传入                 | 复用现有参数，但语义不符                                                  | 低：混淆过滤维度                                    | 低                   |

**问题 B 修复方案对比：**

| 方案                                                       | 实现路径                                             | 效果                                 |
| ---------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------ |
| 修改 Prompt 规则，要求 `【参考资料X·章节名】` 格式（已选） | 在高/中置信度 system prompt 的引用规则行补充格式示例 | 直接有效，LLM 严格遵守指令           |
| 在 `_format_knowledge_detailed()` 内输出编号标题行         | 给每条资料加 `标题: 第X章 XX` 行                     | 辅助措施，和 Prompt 改动配合效果更佳 |
| 后处理：回答后用正则替换 `【参考资料X】` 为含章节的形式    | Server 端后处理，追加章节映射                        | 实现复杂，流式输出难以处理           |

**问题 C 修复方案对比：**

| 方案                                                                | 描述                                                                                                      | 优点                       | 残留问题                                             |
| ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | -------------------------- | ---------------------------------------------------- |
| 将 `save_message()` 移至 `_build_messages()` 之后（已选，基础修复） | 保证上下文快照不包含当前消息                                                                              | 根除"当前消息出现两遍"问题 | 历史回答 A1 仍是强锚点，temperature=0.3 时仍可能相似 |
| 注入多样性提示（已选，补充修复）                                    | 检测 context 中是否存在与当前问题相同的 user 消息，若是则在最后一条 user 消息前插入"请换角度重新解释"指令 | 打破 A1 锚点效果           | 轻微增加 token 消耗                                  |
| 提升 `TEMPERATURE`（可选辅助）                                      | 将 `Config.TEMPERATURE` 从 `0.3` 调至 `0.5~0.6`                                                           | 增加生成多样性             | 影响所有回答，可能降低精确问题的准确性               |
| 使用对话历史摘要替代全量历史                                        | 多轮后将历史压缩为摘要，减少锚点                                                                          | 彻底解决长对话一致性       | 实现复杂，暂不适用                                   |

## 二、解决方案 - 三处独立修复的实施

### 2.1 技术方案

**问题 A 修复：`VectorService.search()` 增加 `threshold` 参数**

`services/vector_service.py` 中 `search()` 方法签名从：

```python
def search(
    self,
    query: str,
    top_k: Optional[int] = None,
    filter_metadata: Optional[Dict] = None
) -> List[Dict]:
    threshold = Config.SIMILARITY_THRESHOLD  # 永远固定
```

改为：

```python
def search(
    self,
    query: str,
    top_k: Optional[int] = None,
    threshold: Optional[float] = None,        # ← 新增可选参数
    filter_metadata: Optional[Dict] = None
) -> List[Dict]:
    top_k = top_k or Config.TOP_K_RESULTS
    threshold = threshold if threshold is not None else Config.SIMILARITY_THRESHOLD  # ← 外部传入优先
```

`services/llm_service.py` 中 `_build_messages()` 的检索调用从：

```python
raw_results = self.vector_service.search(
    query=user_message,
    top_k=top_k
)
```

改为：

```python
raw_results = self.vector_service.search(
    query=user_message,
    top_k=top_k,
    threshold=threshold      # ← 传入分类器给出的动态阈值
)
```

同时，第二层过滤分支（确定 `rag_mode`）也从硬编码 `self.RAG_MEDIUM_CONFIDENCE` 改为使用 `threshold`：

```python
elif max_score >= threshold:          # ← 原为 self.RAG_MEDIUM_CONFIDENCE
    rag_mode = 'medium'
    search_results = [
        doc for doc in raw_results
        if doc.get('score', 0) >= threshold    # ← 同步修改
    ]
```

**问题 B 修复：Prompt 引用格式指令增加章节要求**

在高置信度 Prompt 规则第 2 条，将：

```
2. **必须使用【参考资料X】格式标注引用**
```

改为：

```
2. **引用时必须使用【参考资料X·章节名】格式标注**，X为编号，后面跟该资料的章节名，
   例如：【参考资料1·第3章 指针】【参考资料2·第1章 数组基础】
```

在中置信度 Prompt 规则第 2 条，将：

```
2. 你可以选择性使用，如果使用请标注【参考资料X】
```

改为：

```
2. 如果引用请标注【参考资料X·章节名】，X为编号，后面注明该资料的章节，
   例如：【参考资料1·第5章 函数】
```

同时在 `_format_knowledge_detailed()` 中补充 `section` 字段输出：

```python
source = metadata.get('source', '未知来源')
chapter = metadata.get('chapter', '')
section = metadata.get('section', '')          # ← 新增
chunk_id = metadata.get('chunk_id', 'N/A')
display_location = f"{chapter}" + (f" > {section}" if section else "")

formatted.append(
    f"【参考资料 {i}】[{confidence_tag}]\n"
    f"来源: {source}\n"
    f"章节: {display_location}\n"              # ← 精确到小节
    f"相似度: {score:.1%}\n"
    f"知识块ID: {chunk_id}\n"
    f"内容:\n{text}\n"
    f"{'─' * 40}"
)
```

**问题 C 修复：消息保存时序调整 + 重复问题多样性注入**

_步骤一：调整 `chat_stream()` 中的保存时序_

```python
def chat_stream(self, user_message, session_id=None, max_context=None):
    try:
        # ✅ 修复：先构建上下文（数据库中尚无当前消息），再保存
        messages, referenced_chunks = self._build_messages(user_message, session_id)

        if session_id:
            ChatService.save_message(session_id, 'user', user_message)   # ← 移到之后

        if messages is None:
            yield "抱歉，系统错误，请重试。"
            return
        ...
```

_步骤二：在 `_build_messages()` 第 4 步之后检测重复并注入多样性指令_

```python
# ========== 4. 获取历史上下文 ==========
context = []
if session_id:
    context = ChatService.get_context_for_ai(session_id)
print(f"📚 上下文: {len(context)}条消息")

# ========== 4.5 检测重复问题 ==========
is_repeat = any(
    msg.get('role') == 'user' and msg.get('content', '').strip() == user_message.strip()
    for msg in context
)
if is_repeat:
    print(f"🔄 检测到重复问题，将注入多样性提示")

# ========== 5. 构建消息 ==========
...
# （高/中/普通三种 rag_mode 分支，最终得到 messages）

# ========== 重复问题：在最后一条 user 消息前插入多样性提示 ==========
if is_repeat and messages:
    messages.insert(len(messages) - 1, {
        "role": "system",
        "content": "【注意】该学生问的问题之前已经回答过。"
                   "请换一个角度、使用不同的示例或更深入的分析来重新解释，"
                   "不要重复之前完全相同的回答内容。"
    })

return messages, referenced_chunks
```

### 2.2 实施步骤

#### 步骤1：修改 `services/vector_service.py`

在 `search()` 方法签名中增加 `threshold: Optional[float] = None`，将方法体内的 `threshold = Config.SIMILARITY_THRESHOLD` 改为 `threshold = threshold if threshold is not None else Config.SIMILARITY_THRESHOLD`。

#### 步骤2：修改 `services/llm_service.py`

1. 在 `_build_messages()` 检索调用处追加 `threshold=threshold` 参数
2. 将第二层 `elif max_score >= self.RAG_MEDIUM_CONFIDENCE` 改为 `elif max_score >= threshold`，内部列表推导式同步修改
3. 在获取 `context` 之后、构建 `messages` 之前，增加重复问题检测逻辑
4. 在 `return messages, referenced_chunks` 之前，对重复问题追加多样性提示
5. 在高置信度和中置信度 Prompt 中分别修改引用格式规则
6. 在 `_format_knowledge_detailed()` 新增 `section` 读取，`display_location` 拼接到小节级别
7. 将 `chat_stream()` 中的 `save_message()` 调用移至 `_build_messages()` 返回之后

#### 步骤3：验证

通过后端日志确认：

- 日志中出现"threshold=0.50"（error 类）或"threshold=0.60"（concept 类）等动态值，而非固定 0.65
- 日志中出现"🔄 检测到重复问题，将注入多样性提示"
- AI 回答中出现 `【参考资料1·第X章 XX】` 格式的引用标注
