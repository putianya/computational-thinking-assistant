## 一、关键技术与问题8 - 知识库文件系统与数据库的自动双向同步机制

【描述系统设计阶段考虑到的可能遇到到的关键技术与问题，包括未知解决方法的问题、未使用过的技术等所有可能影响系统开发的点】

本系统的知识库管理模块原本仅支持通过前端上传/删除文档来触发 ChromaDB 向量库和 KnowledgeChunk 数据库表的同步写入。在实际使用中发现，若管理员直接在文件资源管理器中增删 `.md` 文件（例如批量导入经 `preprocess_md.py` 处理后的知识文档），这些变更虽然能在前端"刷新"后显示出来，但对应的知识块不会被导入向量数据库，也不会被统计，导致 RAG 检索失效。与此同时，若直接删除文件，数据库和向量库中的孤立记录也不会被自动清理。核心挑战包括：如何在不侵入现有上传/删除流程的前提下实现双向同步、如何在服务启动时安全地执行异步任务、以及如何在前端提供手动触发入口。

### 1.1 问题描述

1. **文件系统与数据库状态不一致**：前端通过 `GET /api/knowledge/documents` 展示文件列表时，直接扫描 `data/knowledge/` 目录（磁盘状态），而知识块统计来自 `KnowledgeChunk` 表（DB状态），两者可能严重不一致
2. **旁路写入导致向量缺失**：`preprocess_md.py` + 文件管理器的工作流完全绕过了 `import_single_file()` 的 ChromaDB 写入路径，新文件永远不会被向量化
3. **孤立记录污染统计数据**：文件被直接删除后，`KnowledgeChunk` 表中仍保留该文件的所有记录，导致知识块总数统计虚高，且这些孤立向量会干扰 RAG 检索结果相关性
4. **启动时异步任务的安全性**：若在 Flask 应用初始化期间（`create_app()` 内）同步执行数据库查询，可能因应用上下文未就绪而报错；若完全异步执行则需要手动推入 `app_context()`
5. **并发同步冲突风险**：多次快速点击前端"同步"按钮，或启动同步与手动上传同时进行，可能导致 `import_single_file()` 对同一文件并发写入
6. **同步粒度与性能平衡**：全量扫描并对比磁盘/DB 状态在文件数量大时有性能开销，需要评估"增量检测"与"全量对比"的取舍

### 1.2 可能的解决方案

**文件变更检测方案：**
| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 全量diff对比（已选） | 实现简单，无需额外进程，一致性强 | 文件数量多时有扫描开销 | 中小规模知识库（<1000文件） |
| 文件系统监听（watchdog） | 实时响应，无需轮询 | 需要后台守护进程，重启后可能漏事件 | 需要实时同步的生产环境 |
| 文件哈希快照对比 | 能检测文件内容变更（覆盖写） | 需维护快照文件，实现复杂 | 需要检测内容变更的场景 |
| 数据库触发器 | 数据库层面保证一致性 | SQLite不支持跨进程触发器 | PostgreSQL等企业级数据库 |

**启动同步执行方式：**
| 方案 | 优点 | 缺点 | 安全性 |
|------|------|------|--------|
| `create_app()` 内同步执行 | 保证启动完成前同步完毕 | 可能阻塞服务启动，上下文风险高 | ⭐⭐ |
| `WERKZEUG_RUN_MAIN` 守卫 + `threading`（已选） | 只在 worker 进程执行一次，不阻塞主进程 | 需要手动 `sleep(1)` 等服务就绪 | ⭐⭐⭐⭐ |
| Flask `@app.before_first_request` | 框架原生支持，在首个请求时执行 | Flask 2.3+ 已废弃该装饰器 | ⭐⭐⭐ |
| 独立 CLI 命令（`flask sync-knowledge`） | 完全解耦，可手动控制 | 不能自动化，依赖人工执行 | ⭐⭐⭐⭐⭐ |

**孤立记录清理策略：**
| 方案 | 优点 | 缺点 | 数据安全性 |
|------|------|------|-----------|
| 立即物理删除（已选） | 数据干净，节省存储 | 不可恢复 | ⭐⭐⭐ |
| 软删除（`is_active=False`） | 可恢复，有审计记录 | 孤立数据仍占用空间和干扰统计 | ⭐⭐⭐⭐⭐ |
| 归档到单独表 | 保留历史，不干扰主表 | 实现复杂，需要额外迁移 | ⭐⭐⭐⭐ |
| 定时任务清理 | 批量处理，低峰期执行 | 实时性差，孤立数据短期存在 | ⭐⭐⭐ |

**前端触发方式：**
| 方案 | 优点 | 缺点 | 用户体验 |
|------|------|------|---------|
| 独立"同步"按钮（已选） | 意图明确，与"刷新视图"区分清晰 | 需要额外操作 | ⭐⭐⭐⭐ |
| 合并到"刷新"按钮中 | 操作简便 | 用户难以区分轻量刷新与耗时同步 | ⭐⭐⭐ |
| 自动轮询（定时同步） | 完全无感知 | 浪费请求，后台持续开销 | ⭐⭐⭐⭐ |
| 页面加载时自动触发 | 首次打开即最新 | 每次进入页面都有同步耗时，体验差 | ⭐⭐ |

## 二、解决方案1 - 后端双向同步函数与 API 接口设计

### 2.1 技术方案

**核心思路：** 在 `routes/knowledge.py` 中实现一个独立的 `sync_knowledge_directory()` 函数，通过集合差运算完成双向对比，并复用现有的 `import_single_file()` 和向量删除接口，保证逻辑与上传/删除路由完全一致。

**同步逻辑设计：**

```
磁盘文件集合 (disk_files)  ←→  DB来源集合 (db_sources)
        │                              │
   disk - db                      db - disk
        │                              │
   需要导入                        需要清理
        ↓                              ↓
 import_single_file()     delete_documents() + KnowledgeChunk.delete()
        │                              │
   ✅ 写入 ChromaDB              ✅ 清理向量和数据库记录
   ✅ 写入 KnowledgeChunk表
```

**关键技术点：**

1. **集合差运算确定增删集合：**

   ```python
   disk_files = {f.name for f in knowledge_dir.glob('*.md')}
   db_sources = {
       row[0]
       for row in db.session.query(KnowledgeChunk.source).distinct().all()
   }

   to_import = disk_files - db_sources  # 磁盘有、DB无
   to_delete = db_sources - disk_files  # DB有、磁盘无
   ```

2. **延迟初始化向量服务（仅在有清理任务时）：**

   ```python
   if to_delete:
       vector_service = get_vector_service()
   for filename in sorted(to_delete):
       chunks = KnowledgeChunk.query.filter_by(source=filename).all()
       vector_ids = [c.vector_id for c in chunks if c.vector_id]
       if vector_ids:
           vector_service.delete_documents(vector_ids)
       KnowledgeChunk.query.filter_by(source=filename).delete()
       db.session.commit()
   ```

3. **结构化返回结果供上层使用：**

   ```python
   result = {
       'imported': [],   # 成功导入的文件名列表
       'deleted': [],    # 成功清理的文件名列表
       'errors': []      # {'file': filename, 'error': str(e)}
   }
   ```

### 2.2 实施步骤

#### 步骤1：在 `routes/knowledge.py` 末尾实现同步函数

```python
# backend/routes/knowledge.py

def sync_knowledge_directory():
    """
    将磁盘上的 .md 文件与数据库 KnowledgeChunk 记录进行双向同步。
    - 磁盘有、DB 无 → 导入（import_single_file）
    - DB 有、磁盘无 → 删除知识块 + 向量
    """
    from scripts.import_knowledge import import_single_file

    knowledge_dir = Path(BASE_DIR) / 'data' / 'knowledge'
    result = {'imported': [], 'deleted': [], 'errors': []}

    if not knowledge_dir.exists():
        print("⚠️ 知识库目录不存在，跳过同步")
        return result

    disk_files = {f.name for f in knowledge_dir.glob('*.md')}
    db_sources = {
        row[0]
        for row in db.session.query(KnowledgeChunk.source).distinct().all()
    }

    # ---- 导入新增文件 ----
    for filename in sorted(disk_files - db_sources):
        print(f"📥 同步新文件: {filename}")
        try:
            import_single_file(knowledge_dir / filename)
            result['imported'].append(filename)
        except Exception as e:
            result['errors'].append({'file': filename, 'error': str(e)})

    # ---- 清理孤立记录 ----
    to_delete = db_sources - disk_files
    if to_delete:
        vector_service = get_vector_service()
    for filename in sorted(to_delete):
        print(f"🗑️ 清理已删除文件的记录: {filename}")
        try:
            chunks = KnowledgeChunk.query.filter_by(source=filename).all()
            vector_ids = [c.vector_id for c in chunks if c.vector_id]
            if vector_ids:
                vector_service.delete_documents(vector_ids)
            KnowledgeChunk.query.filter_by(source=filename).delete()
            db.session.commit()
            result['deleted'].append(filename)
        except Exception as e:
            db.session.rollback()
            result['errors'].append({'file': filename, 'error': str(e)})

    return result
```

#### 步骤2：注册手动触发 API 路由

```python
@knowledge_bp.route('/api/knowledge/sync', methods=['POST'])
@login_required
@require_permission('upload_doc')
def sync_knowledge():
    """手动触发知识库目录同步"""
    try:
        result = sync_knowledge_directory()

        msg_parts = []
        if result['imported']:
            msg_parts.append(f"导入 {len(result['imported'])} 个新文件")
        if result['deleted']:
            msg_parts.append(f"清理 {len(result['deleted'])} 个已删文件的记录")
        if not msg_parts:
            msg_parts.append("无变更，已是最新")

        return jsonify({
            'status': 'success',
            'message': '；'.join(msg_parts),
            'data': result
        })

    except Exception as e:
        traceback.print_exc()
        return jsonify({'status': 'error', 'message': f'同步失败: {str(e)}'}), 500
```

#### 步骤3：在 `app.py` 中注册启动时自动同步

```python
# backend/app.py
if os.environ.get('WERKZEUG_RUN_MAIN') == 'true':
    # ... 现有启动日志 ...

    import threading

    def _startup_sync():
        import time
        time.sleep(1)  # 等待 Werkzeug worker 完全就绪
        with app.app_context():
            try:
                from routes.knowledge import sync_knowledge_directory
                r = sync_knowledge_directory()
                imported = len(r['imported'])
                deleted = len(r['deleted'])
                if imported or deleted:
                    print(f"🔄 启动同步：新增 {imported} 个文档，清理 {deleted} 条孤立记录")
                else:
                    print("🔄 启动同步：知识库已是最新，无变更")
            except Exception as e:
                print(f"⚠️ 启动同步失败（不影响服务运行）: {e}")

    threading.Thread(target=_startup_sync, daemon=True).start()
```

**关键设计点：**

- `WERKZEUG_RUN_MAIN == 'true'` 保证在 Flask debug 模式下只有 reloader 产生的子进程（真正处理请求的 worker）执行同步，避免重复运行
- `time.sleep(1)` 留出 SQLAlchemy 连接池初始化时间
- `daemon=True` 确保主进程退出时线程不会阻塞关闭

## 三、解决方案2 - 前端同步按钮与状态反馈设计

### 3.1 技术方案

在 `KnowledgeBase.vue` 的操作栏中新增独立"同步"按钮，与原有"刷新"按钮职责分离：

| 按钮 | 调用接口                       | 耗时                     | 说明               |
| ---- | ------------------------------ | ------------------------ | ------------------ |
| 刷新 | `GET /api/knowledge/documents` | 极快（< 200ms）          | 仅刷新列表视图显示 |
| 同步 | `POST /api/knowledge/sync`     | 较慢（取决于新文件数量） | 写入向量库和数据库 |

### 3.2 实施步骤

#### 步骤1：在 `knowledge.js` 中新增 API 方法

```javascript
async syncDocuments() {
  const response = await fetch(`${API_BASE_URL}/knowledge/sync`, {
    method: "POST",
    headers: getAuthHeaders(),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || "同步失败");
  }

  return response.json();
},
```

#### 步骤2：在 `KnowledgeBase.vue` 中添加状态变量和处理函数

```javascript
// Script 部分
const isSyncing = ref(false);

async function handleSync() {
  isSyncing.value = true;
  try {
    const response = await knowledgeAPI.syncDocuments();
    const { imported, deleted, errors } = response.data;
    let msg = response.message;
    if (errors && errors.length) {
      msg += `\n⚠️ ${errors.length} 个文件处理失败`;
    }
    alert(`✅ 同步完成：${msg}`);
    await loadDocuments(); // 刷新文件列表
    await loadStats(); // 刷新统计数据
  } catch (e) {
    alert(`❌ 同步失败：${e.message}`);
  } finally {
    isSyncing.value = false;
  }
}
```

#### 步骤3：在模板中插入按钮（置于"刷新"与"上传文档"之间）

**遇到的问题及解决：**

1. **`WERKZEUG_RUN_MAIN` 条件在非 debug 模式下为 False**
   - 问题：生产模式直接用 `python app.py` 启动时，环境变量 `WERKZEUG_RUN_MAIN` 不存在，启动同步线程不会被触发
   - 解决：补充 `or not Config.DEBUG` 条件，或改用 `@app.before_first_request`（兼容旧版 Flask）

2. **`to_delete` 循环的 `vector_service` 作用域问题**
   - 问题：`if to_delete: vector_service = get_vector_service()` 的赋值在条件块内，Python 在集合为空时变量未定义，但循环本身不执行，实际不会报 `NameError`，但逻辑上令人困惑
   - 解决：将 `vector_service` 懒初始化移入循环体内的 `try` 块，或在函数头声明 `vector_service = None` 后按需初始化
